Sidewalk-centered synthetic data for urban robot perception, generated in CARLA using six European-inspired scenarios.

Perception from the sidewalk

Road-centered training data can limit sidewalk segmentation when the camera itself is positioned on a sidewalk. This project generates synthetic scenes from a low camera viewpoint and studies how synthetic data, real driving data, and limited target-domain annotations affect real-world segmentation.

The CARLA scenarios include sidewalk surfaces, bicycle lanes, tactile paving, and curb ramps. Data acquisition varies weather, time of day, and pedestrian density.

Data

The dataset

The synthetic collection contains 2,086 paired RGB images and semantic annotations across six scenarios. Images were captured at 1280 × 720 pixels, with a 90° field of view, camera height of 0.6 m, and pitch of −4°.

Step by step

Generate data with CARLA

This workflow uses the supplied packaged Linux runtime with the project’s modified maps. It describes the generate_data.py example; inspect other scene scripts for their own settings.

1. Prepare the requirements

  • A Linux computer with a GPU and graphics drivers capable of running CARLA 0.9.15.
  • The project archives CARLA_0.9.15-dirty.tar.gz and CARLA_generation.zip.
  • A Python environment with a compatible CARLA 0.9.15 client, NumPy, and Pillow.

Use a Python version supported by your CARLA client. If a matching wheel is included under PythonAPI/carla/dist, install that wheel in your environment.

python -m pip install numpy Pillow
python -c "import carla, numpy, PIL; print('Imports successful')"

The import check succeeds only after the compatible CARLA client is installed.

2. Extract the runtime and scripts

Run these commands from the directory containing the downloaded archives:

mkdir -p carla_runtime generation_scripts
tar -xzf CARLA_0.9.15-dirty.tar.gz -C carla_runtime
unzip CARLA_generation.zip -d generation_scripts

Locate CarlaUE4.sh inside the extracted runtime. Archive nesting may vary. The supplied archive contains a complete runtime; an editable Unreal source project is not included.

3. Configure the selected scene

Open generate_data.py in a text editor. The example uses settings in the source code rather than command-line options.

  • Change OUT_ROOT to a writable output directory on your computer.
  • Keep the scene’s MAP_NAME and coordinate bounds together. The example uses /Game/Carla/Maps/Town10HD.
  • Check camera settings, weather, time of day, actor counts, and frames per condition.

Use a new output directory for each experiment. The example connects to 127.0.0.1:2000.

4. Launch CARLA

In a terminal, change to the directory containing CarlaUE4.sh and run:

./CarlaUE4.sh

If permission is denied, run chmod +x CarlaUE4.sh and retry. Wait for CARLA to start and keep this terminal open.

5. Start generation

Open a second terminal, activate your CARLA Python environment, and change to the directory containing the generation script.

python generate_data.py

The script loads its configured map, applies the scene settings, and writes images to OUT_ROOT. Run scene scripts sequentially against one CARLA server.

6. Inspect the generated pairs

The example writes files using this structure:

<OUT_ROOT>/<weather>/<time_of_day>/<density>/run_001/
    rgb/000000.png
    sem_raw/000000.png
    sem/000000.png
  • rgb: RGB camera images.
  • sem_raw: raw semantic images with class IDs encoded in the red channel.
  • sem: colorized semantic visualizations.

Matching filenames within the same run identify paired images. Colorized visualizations are not single-channel training masks.

7. Prepare six-class masks

Extract dataset_preparation.zip and update the paths in each script before running it.

python -m pip install numpy Pillow pandas scikit-learn tqdm
python classid.py
python convert_labels_reduced.py

classid.py extracts IDs into labels; convert_labels_reduced.py writes the six-class masks into labels_reduced. Check the expected folder layout: the generation example includes run directories that may require reorganization for preparation scripts.

Troubleshooting

Python cannot import CARLA

Activate the correct environment and install a CARLA 0.9.15 client compatible with its Python version.

The script times out or the map is missing

Wait for the server to be ready and verify the host and port. Launch the supplied runtime so that the modified maps are available.

Fewer images are generated than expected

The example may skip conditions if a path is too short or sensor frames are unavailable. Check terminal messages and scene coordinate bounds.

Exact image-for-image reproduction is not guaranteed: the example uses random sampling without a fixed seed. These instructions are based on the project README; this website has not independently tested the CARLA runtime.

Evaluation

Synthetic and real data together

SegFormer-B0 was evaluated on 35 held-out real sidewalk images. Joint training used a fixed-size collection of 1,668 images. Supervised target-domain adaptation subsequently used 51 additional real images, separate from the evaluation set.

Selected fixed-size and adaptation experiments
ConfigurationmIoUSidewalk IoU
C0 · Cityscapes only0.3950.067
C1 · 50% Cityscapes + 50% synthetic0.5450.733
C1 + supervised target-domain adaptation0.6330.771

The 50/50 mixture achieved the best result among the tested fixed-size mixing configurations. Sequential target-domain fine-tuning achieved the best overall result. The small real evaluation set limits generalization of these findings.
